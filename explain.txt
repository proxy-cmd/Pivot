PIVOT — WHAT THIS PROJECT IS

Pivot is a local-first, metadata-driven business data intelligence platform. It is not meant to be a generic dashboard. It takes an uploaded dataset, preserves the original source, profiles it, remembers its metadata, detects quality risks, records data lineage, supports safe deterministic data transformations, and answers questions using retrieved source context.

WHAT IS IMPLEMENTED AND WORKING

1. Full-stack architecture
   - React/Vite front end for the executive dashboard, upload flow, simulator, and live analyst experience.
   - FastAPI Python back end for data operations and AI orchestration.
   - SQLite metadata database stored locally in data/pivot.db.
   - Dockerfile and docker-compose configuration for a single-container deployment.

2. Dataset ingestion and persistence
   - CSV, Excel, JSON and Parquet are accepted by the API.
   - Raw uploads are written unchanged into data/files. This is version 0 / source of truth.
   - Every upload receives a dataset session ID.
   - A SHA-256 dataset fingerprint is calculated after canonical CSV serialization.

3. Metadata and semantic understanding
   - Profiles store row/column counts, inferred role, date/numeric/money fields, likely IDs, primary-key candidates and PII flags.
   - Each column gets a semantic role, confidence score and simple evidence string.
   - Profile data is stored in SQLite and exposed by GET /api/datasets/{id}.

4. Quality engine
   - Finds missing values, exact duplicate rows, invalid dates, negative operational values, IsolationForest outliers and leading/trailing whitespace.
   - Every reported issue includes an impact and a suggested resolution.
   - The score is a transparent penalty-based quality score, not a fake AI number.

5. Lineage and transformations
   - The metadata database keeps version entries and events.
   - Source data is never modified.
   - Trim text, remove duplicates, normalize column names and parse dates are deterministic transformations.
   - Planning an action records it as approval-required. Executing it writes a distinct output CSV and a lineage record.

6. RAG and chat
   - Dataset schema and samples, plus PDF and JSON document text, are chunked and stored with the dataset session.
   - Local TF-IDF retrieval picks relevant chunks for a question.
   - If GEMINI_API_KEY is configured in backend/.env, Gemini receives only dashboard facts plus retrieved chunks and is instructed to cite sources and avoid invention.
   - Without Gemini, the API reports that context was found instead of pretending to have an AI answer.
   - The dashboard shows live grounding and a typing state. The API also has an SSE event endpoint for live clients.

7. Analytics and safety
   - Linear-regression forecast with residual-based confidence bands.
   - Scenario calculator for price, marketing and supplier-cost changes.
   - Read-only SQL validation: SELECT/WITH are allowed; writes, DDL, PRAGMA and multi-statements are blocked.
   - Tests cover forecast, simulation, retrieval and SQL blocking.

HOW TO DEMO IT

1. Follow README.md to start the API and the web app.
2. Upload a small CSV or Excel sales/orders file.
3. Point out the data quality badge, detected data type/role, and that original data remains untouched.
4. Ask a question in the Pivot analyst card after adding GEMINI_API_KEY to backend/.env.
5. Call http://localhost:8000/docs to show the API, session endpoints, SSE events, RAG chat and safe SQL validation.
6. Run pytest backend/tests to demonstrate that important core behaviors are checked.

WHAT IS NOT IMPLEMENTED YET — IMPORTANT TO SAY HONESTLY

This is a production-oriented foundation, not a finished enterprise SaaS. It does NOT yet include authentication/RBAC/multi-tenancy, PostgreSQL/MySQL/Snowflake/BigQuery connectors, cloud storage, worker queues, schedules, browser-level real-time collaboration, actual vector embeddings/BM25 reranking, external database query execution, visual lineage graph, full transformation library, model registry, AutoML, dashboards editor, OAuth/SSO, Redis, Celery, observability stack, CI/CD, Kubernetes, compliance controls or a managed production deployment.

WHY THOSE THINGS ARE NOT FAKE-IMPLEMENTED

Enterprise connectors require credential storage and security reviews. Multi-tenancy requires identity, authorization, data isolation and audit policy. Reliable background jobs require a queue and separate workers. Semantic vector search needs an embedding provider or local embedding model plus a vector store. Claiming these are complete without those foundations would be misleading.

NEXT REAL PRODUCTION STEPS

1. Replace SQLite with PostgreSQL and data/files with S3/MinIO.
2. Add auth, organizations, RBAC, row-level policies and audit logging.
3. Add SQLAlchemy connector framework with encrypted credentials and read-only query execution.
4. Add Redis + Celery/RQ for ingestion/profiling/report jobs and schedules.
5. Replace TF-IDF-only retrieval with hybrid BM25 + embeddings + metadata filters + reranking.
6. Add tests, GitHub Actions, tracing, metrics, backups and secret management before accepting customer data.

ONE-SENTENCE PITCH

Pivot gives every business dataset a memory: preserved source, metadata, quality context, lineage and evidence-grounded AI assistance—so teams can spend less time preparing data and more time trusting decisions.
